# Embedding an Exercise in an LMS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An exercise link with `&embed=1` behaves well inside a 700–1000 px iframe on a Blackboard Ultra or Canvas page — card folded to a tab that says "open instructions", a plain wheel scrolls the page, a pop-out and a full-screen button on the strip — and a lecturer can copy the iframe snippet from the app and read how to place it.

**Architecture:** One boot-time flag (`EMBED`) read from the query string in `main.js`, consulted by `DOCK`, the wheel listener, `KEYS` and the strip; an optional `when` predicate on strip items; a snippet button in `RIG`'s panel; a docs page; one `ui-smoke.mjs` case. No new file in `js/`, no wire-format change, no physics touched.

**Tech Stack:** Zero-dependency classic scripts, CDP browser gates (Node 22+), Python checkers.

**Spec:** `docs/superpowers/specs/2026-09-10-embed-design.md` — read it first; it records the decisions, the measured frame sizes and their reasons.

## Global Constraints

- **Zero dependencies, classic scripts** — no ES modules, no fetch, no build step in `index.html` / `js/*` / `css/*` (AGENTS.md; the app boots from `file://`).
- **Notation** — nothing here names a physical quantity; keep it that way (no `y` for the vertical anywhere, `check_notation.py` reads the docs too).
- **Rig wire format stays v2** — the snippet and the pop-out READ `RIG.link()`; nothing is added to the payload.
- **The panel toggles stay self-configuring** — `embed=1` hides nothing a student needs; it folds. The `⋯` show-all and the strip's families are untouched.
- **UI profiles still win** — `buildToolbar` filters by `UIMODE.allows` first and `when` second; a profile that hides `meta` hides these buttons too.
- **Every commit message ends with** `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- **Instant gates green after every task:** `python3 exercises/_runner/check_pack.py && python3 exercises/_runner/check_notation.py && node test/geom-test.mjs && node test/recon-test.mjs` (on this Windows machine `python` may be the spelling — try `python3` first). `node test/ui-smoke.mjs` after Tasks 1, 3, 5; `node exercises/_runner/smoke.js --only=api,rig` once before the branch is pushed.
- Working directory: the worktree root (`.claude/worktrees/embed`), branch `worktree-embed`. Never `cd` to the main checkout.

### Task 2: The wheel yields to the page

**Files:**
- Modify: `js/main.js` — the canvas `wheel` listener (~line 3325), `KEYS.LINES` (~line 1849)

**Steps:**

- [ ] **Step 1: The listener.** Replace the body with:
  ```js
  canvas.addEventListener("wheel", (e) => {
    // Embedded, a plain wheel is the LMS page scrolling past; the frame is
    // not scrollable, so leaving the event alone chains it to the parent.
    // Ctrl + wheel zooms — the same key a trackpad pinch already reports.
    if (EMBED && !e.ctrlKey) { wheelHint(); return; }
    e.preventDefault();
    const [px, py] = pointerPx(e);
    zoomAt(px, py, Math.exp(-e.deltaY * (e.ctrlKey ? 0.01 : 0.0022)));
  }, { passive: false });
  ```
  `wheelHint` shows a toast ONCE per page: title "Ctrl + scroll zooms the
  flume", body "Open in a new tab for the full window." (a closure-scoped
  `let hinted = false`). Use the existing `showToast`.

- [ ] **Step 2: The shortcut sheet.** `KEYS.LINES` is a static array; make the
  wheel row `[EMBED ? "ctrl + wheel" : "wheel", "zoom"]`. `KEYS` is declared
  after `EMBED` (Task 1 put the flag near `state`), so the const is in scope.

- [ ] **Step 3: Check by hand.** `?ex=HJ-1&embed=1`: a plain wheel over the
  water does not zoom and shows the toast once; ctrl + wheel zooms. `?ex=HJ-1`:
  wheel zooms as before. Confirm nothing scrolls in the plain tab either way
  (the page has no overflow).

- [ ] **Step 4: Instant gates; commit** — "Embedded, a plain wheel scrolls the page and ctrl + wheel zooms".

### Task 3: Full screen and pop-out on the strip

**Files:**
- Modify: `js/main.js` — `ICONS` (~line 1035), `TOOLBAR` `meta` group (~line 1655), `buildToolbar` filter (~line 1725), the keydown switch (~line 3340), a `fullscreenchange` listener beside the `resize` listeners (~line 3264)

**Interfaces:**
- Strip items gain an optional `when: () => boolean`; absent means shown.
- `stripEmbed(url)`: returns `url` with the `embed` query parameter removed (use `new URL(url)`, `searchParams.delete("embed")`, `toString()`; a `#rig=` fragment survives `URL`).

**Steps:**

- [ ] **Step 1: `when` in `buildToolbar`.** Where items are filtered —
  `group.items.filter((it) => UIMODE.allows(group.family, it))` — add
  `&& (!it.when || it.when())`, with a two-line comment: profile first, then a
  boot-time capability; `syncToolbar` does not re-read `when`, so put nothing
  in it that changes after boot.

- [ ] **Step 2: Icons.** Two `ICONS` entries in the 20 × 20 stroke style:
  - `fullscreen`: four corner brackets, e.g. `<path d="M3.5 7.5v-4h4M16.5 7.5v-4h-4M3.5 12.5v4h4M16.5 12.5v4h-4"/>`
  - `unfullscreen`: the same brackets pointing inward, e.g. `<path d="M7.5 3.5v4h-4M12.5 3.5v4h4M7.5 16.5v-4h-4M12.5 16.5v-4h4"/>`
  - `popout`: a box with an arrow leaving its corner, e.g. `<path d="M8 4H4.5A1.5 1.5 0 0 0 3 5.5v9A1.5 1.5 0 0 0 4.5 16h9a1.5 1.5 0 0 0 1.5-1.5V11"/><path d="M11 3h6v6M17 3l-7 7"/>`

- [ ] **Step 3: The two items,** in `meta` after `panelBtn`:
  ```js
  { id: "fsBtn", icon: () => (document.fullscreenElement ? "unfullscreen" : "fullscreen"),
    label: () => (document.fullscreenElement ? "Exit full screen" : "Full screen"), key: "F",
    hint: "The whole screen for the flume — inside a module page, the way out of the frame",
    on: () => !!document.fullscreenElement,
    when: () => !!document.fullscreenEnabled,
    act: () => toggleFullscreen() },
  { id: "popBtn", icon: "popout", label: "Open in a new tab",
    hint: "This exercise, and what you have drawn, in a full window",
    when: () => EMBED,
    act: () => popOut() },
  ```
  `toggleFullscreen()`: `document.fullscreenElement ? document.exitFullscreen() : document.documentElement.requestFullscreen()`, each `.catch(() => {})`.
  `popOut()`: open synchronously, navigate when the link resolves —
  ```js
  const w = window.open("", "_blank"); if (!w) return;   // blocked: nothing to do
  w.opener = null;
  RIG.link().then((u) => { w.location = stripEmbed(u); })
            .catch(() => { w.location = stripEmbed(location.href.split("#")[0]); });
  ```
  Check `RIG.link()` with no argument encodes the current state (rig.js line ~309: `link(o)` → `encode(o)`; confirm `encode` defaults to `save()` — if it does not, pass `RIG.save()` or whatever the panel's `share()` passes).

- [ ] **Step 4: Sync on change.** `addEventListener("fullscreenchange", () => syncToolbar());` beside the `resize` listeners. The `resize` that accompanies it already runs `DOCK.sync(); fitBar(); applyAutoVex();`.

- [ ] **Step 5: The F key.** In the keydown switch, confirm `"f"` is unbound (grep `case "f"` / `k === "f"`), then add it calling `toggleFullscreen()`. Note `requestFullscreen` needs a user gesture; a keypress is one. Add `["F", "full screen"]` to `KEYS.LINES`.

- [ ] **Step 6: Look.** Full window: the full-screen button appears in the meta group; F and the button toggle it; the icon and label swap. `?ex=HJ-1&embed=1`: the pop-out appears; clicking it opens a new tab on `?ex=HJ-1#rig=…` with no `embed`, the card docked, and any wall you drew present. Serve from `http.server` (not `file://`) for the pop-out test, so `history.replaceState` and clipboard behave.

- [ ] **Step 7: Instant gates; `node test/ui-smoke.mjs`** (the strip cases count buttons against `APP.ui.TOOLBAR` — `specCount` is the spec's total, `buttons` the rendered; a `when`-hidden item breaks `eq("the strip renders the whole spec", …)`. Fix the probe to count only items whose `when` passes, and say why in a comment.) **Commit** — "Full screen and, inside a frame, a way out to a new tab".
